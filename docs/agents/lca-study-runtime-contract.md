# Study runtime v2

`app_lca_study` accepts authenticated POST JSON under `lca.study-api.v2`, bundle `2.0.0`. Offline P0 `lca.study-api.v1` and its fixtures remain unchanged and are rejected by this endpoint. Version 2 explicitly changes source acquisition, profiles, typed artifact retrieval, supported overrides and team resource grants. It does not negotiate v1 execution or fall back to a legacy numerical route.

## Transport and admission

OPTIONS uses shared CORS without actor/domain work. Other methods return 405. POST verifies a Supabase actor JWT through the existing claims-first boundary before reading domain input. A service API key is not an actor. CLI/MCP carry the same actor access token; no password exchange, private queue or alternate bearer classifier is added.

The body is bounded at 256 KiB of actual bytes, including chunked requests, and must be UTF-8 JSON with `application/json` (optionally UTF-8 charset). One 25-second deadline and request cancellation signal cover authentication, body, RPC and artifact work. Timeout returns `DEADLINE_EXCEEDED`; the SDK requests and stream reader receive cancellation. A synchronous callback is not a qualified runtime dependency.

Every JSON response has version/request identity, `ok` and a strict resource/error union. A valid submitted request ID is echoed after authentication and bounded parsing; malformed or unauthenticated envelopes receive a server-generated ID. HTTP errors retain this v2 envelope, including 401, 405, 413 and 504. Errors contain fixed codes/rules/messages, never SQL/provider details, input values or credentials. Responses use `Cache-Control: no-store`. Unknown schema is `UNSUPPORTED_SCHEMA`; input shape/intent errors are `INVALID_REQUEST`.

`STUDY_RUNTIME_CONFIG` is a strict JSON deployment allowlist with `{type: capabilities, contractVersion: 2.0.0, runtimeEnabled, operations, profiles}`. Each profile is `{profileId, calculationContractRef}`. Missing configuration disables domain operations and admits only authenticated capability read. The database's actor-specific capability projection further narrows this list; it cannot expand deployment admission. Defining a profile or having a parser does not qualify it. Enable only exact Database/Worker/Edge revisions, producer protocol, task wiring and numerical evidence qualified together.

P1 supports Study/Revision/Scenario/source acquisition/preparation/Run recovery and typed artifact retrieval. Analysis, report, review, export and ReportShare production are unavailable. Their v2 request shapes remain recognized so unsupported work fails explicitly; no independent review is downgraded. P1 `member.set` manages Study team grants, not report disclosure: owner-only, current same-team eligible recipients, `editor|viewer|null`, Study CAS and live revocation. Personal Studies remain owner-only; no anonymous grant, account discovery or automatic team grant exists. Database owns current membership and resource-role checks on every command, read, receipt replay and grant update.

## RPC and producer boundaries

Actor reads use `api.qry_study_v1(p_request)`; writes use `api.cmd_study_v1(p_request)`. Their internal function version is independent of the public wire. The SDK forwards the original verified actor Bearer and selects `api`; no actor ID or producer evidence is accepted in public requests. RPC replies are `{ok:true,data:<variant>}` or `{ok:false,code:<fixed Study code>}`. Database owns live permissions, cursor binding, content identity, idempotency, locking, CAS and worker-job transactions. Edge validates the returned variant and its selected identities before disclosure. Reads never submit jobs.

`revision.freeze` obtains a database-minted short-lived `{kind: revisionValidationIntent, intentId, expiresAt, revision, preparation}`. Edge compares the exact CAS/hash/model/definition/preparation and qualified profile. Its server validator obtains the prepared input through an actor-authorized artifact capability, verifies the original bytes and strict Worker `lca.study-prepared-input.v1` wire, and checks model/profile/calculation identities, exact method ID/version membership, reference flow/unit and bounded positive functional amount. Worker owns model compilation and fingerprints; Edge does not recompute them. `PreparedInput.sourceHash` binds exact Worker SourceInput bundle bytes, not the exporter snapshot bytes; W06 owned-task provenance must bind those distinct domains. Normalized source identities retain only eligibility state 0 or 100, not actor/owner IDs, and explicit amount overrides remain in model provenance. Base preparation has no study binding; adoption of a prior Scenario preserves its historical binding. A new Scenario compilation binds its frozen Study definition and selected order.

Only the service client calls `svc_study_revision_freeze_consume_v1(p_intent_id,p_outcome,p_error_code)`. Database consumes the bound intent under the current original actor/client/grant and target lock, rejecting changed content, expired **unconsumed** intent or withdrawn authority before atomically storing frozen/passed. Database time is authoritative for intent expiry at actor issue/replay and service consumption. Edge keeps strict ISO timestamp structure and its independent monotonic request deadline; its host wall clock is not a final domain-expiry veto. After a successful commit, a same-key actor retry rechecks current authority and returns the committed revision response, even after the old intent TTL, without revalidating or freezing again. A lost success response cannot strand recovery on the cached intent; expiry never permits an unconsumed intent to commit. Actor requests cannot send an intent, validation outcome or passed marker. Failure/unavailability does not freeze or persist a failed validation state. `passed` is structural/identity qualification, not scientific applicability or factor completeness. Missing factors remain Worker diagnostics.

Model preparation and Run completion use existing owned `worker_jobs`; worker leases and trusted service callbacks install producer results. No public request may set `completed`, model/input hashes or a result artifact. Study team reads/cancellation use the Study façade rather than the generic requester-only worker endpoint. W06 owns exact lease fencing, cancellation/late-result arbitration and task registration.

`scenario.create` with a distinct frozen same-Study parent creates a new Scenario revision ID while retaining that parent's stable `scenarioId`. A null parent allocates a new alternative and stable Scenario ID; callers never submit that ID. Overrides replace the complete explicit layer against the selected frozen StudyRevision, including an empty array that clears the layer. There is no implicit parent-layer merge. To clone as a different alternative, use null parent and explicitly copy/edit the desired overrides; no fork API or new wire field is introduced.

## Client request recovery

Before a mutating dispatch, clients must durably retain the exact versioned request/envelope, idempotency key, selected Study/resource and expected revision/hash. A transport outcome or chat message is not that ledger. After a lost reply or process restart, use the saved intent for exact-key readback under current authorization; do not infer success, create a replacement key automatically or reconstruct scope from a provider error. Server receipt replay preserves the original resource and does not repeat revoked grants or create a second job. CLI owns its eventual durable local implementation; the runtime qualifier keeps its own private request ledger before dispatch to qualify this boundary.

Administrative extraction of an existing database receipt can repair a failed development harness only under the owning isolated fixture. It is recorded separately and never counted as ordinary actor/client recovery evidence. The corrected qualifier must separately prove restart recovery from its own saved request ledger.

## Scoped task recovery and cleanup

Public generic job read/list/feed/count/cancel/retry/enqueue/result interfaces exclude every `study.*` job before pagination/counts; a historical requester or unrelated operator role is not current Study authorization. Trusted worker claim and heartbeat remain on the canonical queue.

Use `task.read` or mutating `task.cancel` with `{studyId, resource: {type, id}}`, where type is exactly `modelSourceAcquisition`, `modelPreparation` or `run`. The server derives the canonical job; caller-supplied job IDs are rejected. Cancel also requires its idempotency key and bounded reason. Current Study read/write grants respectively apply, and task cancellation remains available for authorized cleanup of archived Studies. A task reply contains only the exact Study/resource, job ID/status, safe allowlisted phase, finite progress in [0,1] or null, and a fixed allowlisted error code or null. Raw diagnostics, payloads, source authorization, lease tokens and storage locators never enter it. A cancellation race follows the existing queue arbiter; an already committed successful result is not rewritten.

## Resumable source acquisition and artifacts

`model.source.resolve` retains exact `{studyId, originRef}` input but returns `modelSourceAcquisition` with `{acquisitionId, studyId, originRef, execution:{jobId,status}, snapshot}`. `model.source.read` recovers an acquisition by ID; typed Study resource pages also enumerate acquisitions. Only completed acquisition has a nonnull immutable snapshot, and its Study/origin must match exactly. Failed/queued acquisitions expose no manufactured hash. Server-owned exporter/task mechanisms must bind authorized exact versions, original artifact bytes, issuer and licensing before service completion. A mutable API wrapper, normalization fallback or synthetic specimen cannot issue a source identity. Resolution is enqueue/read recovery, never an infinite blocking export.

For snapshot-source `model.prepare`, ordered exact `methodRefs` are required before the StudyRevision exists. The not-yet-qualified runtime v2 / bundle 2.0.0 candidate explicitly adds optional base-only `cutoffs` in Edge #537; prior request bodies remain legal and no public response field is added. Omission and an explicit empty array declare no exclusions. Each cutoff is `{port: {instanceId, exchangeId}, reason}`: at most 256 unique ports, ASCII letters/digits/underscore/hyphen IDs of 1–128 characters, and nonblank bounded reason text of at most 1024 codepoints under the existing control/UTF-8 rules. The exact candidate source must be qualified with Database #895 and Worker #356 before this extension is used; these semantics are not inferred from a previously pinned parser. Scenario-source preparation must omit both `methodRefs` and `cutoffs` (including an explicit empty cutoff array), and derive the frozen base methods/cutoffs. Database retains their immutable preparation-scope binding; a new response field is not required merely to echo the request. Scenario overrides replace the complete current layer relative to the selected StudyRevision and do not merge the parent Scenario layer. Every v2 preparation readback retains its exact ordered `methodRefs`, including pending records, so recovery does not depend on a vanished chat/request body. A StudyRevision adopts that exact stored selection. The first qualified `lca.study-explicit-v1` override grammar is only `/instances/{id}/exchanges/{exchangeInternalId}/amount` with finite numeric replacement; unsupported provider/parameter/boolean/null operations fail. Worker owns all interpretation and numerical limits.

`artifact.read` selects one Study and exact typed artifact descriptor, never a URL/bucket/object key. The actor RPC returns only an opaque `{kind: artifactReadIntent, intentId, expiresAt, studyId, artifactRef}` after current resource/source checks. Even a direct authenticated PostgREST caller receives no locator. Edge calls service-only `svc_study_artifact_read_resolve_v1(p_intent_id)` before and after bounded download and exact size/SHA-256 verification. Each resolve uses Database time and rechecks the original actor/client, exact reference and all current source rights; Edge does not veto expiry using its host wall clock. Only this service reply contains `{kind: artifactCapability, studyId, artifactRef, storageBucket, storageObjectPath}`. Edge validates the server-derived locator and uses server Storage credentials; a denied/expired or changed second resolve prevents disclosure. It then returns `{type: artifact, studyId, artifactRef, encoding: base64, bytes}` without the locator. W06 public byte kinds are modelInput/runResult; report/analysis content requires its later capability. Raw modelSource packets are always `DISCLOSURE_DENIED`, including for Study owners: their private authorization/actor/owner metadata is a service-only compiler input. Opaque source references remain visible for provenance. A future safe source projection requires a distinct artifact identity; private fields must never be redacted while retaining the original hash.

Inline retrieval has an explicit 4 MiB byte limit. Larger descriptors fail `PAYLOAD_TOO_LARGE`, never truncate or bypass verification with an unchecked URL. This transport limit is distinct from Worker's compiler artifact/source bounds; consumers and rollout qualification must account for it. Streamed or chunked large-artifact delivery requires a separately versioned protocol. Expiring download links and credentials never enter durable public artifact references.

## W06 source and task qualification

The admitted acquisition format is the separately versioned `lca.study-source-snapshot.v1` JSON snapshot issued from Database-authorized exact dataset rows. It is not an original ZIP or an acquired file representation. `sourceAuthorization.sourceEncoding` names `postgresql.json-text.utf8.v1`: document digests bind those exact authorized UTF-8 JSON text bytes, while the snapshot artifact digest binds the exact issued JSON envelope bytes. The later compiler SourceInput byte hash and normalized model/input/calculation identities retain their separate owner-defined domains.

The envelope's `sourceAuthorization`, `source.actorId` and per-document owner metadata remain service-only. Worker jobs contain only typed IDs; their generic receipt is `lca.study-job-receipt.v1`, not a source payload or numerical result. Database owns current source rights, Study/client grants, leases, reconciliation and cancellation arbitration. The native Worker verifies authorized source scope and original bytes, compiles declared methods/cutoffs, freezes factor selections for Scenario preparation, and commits through lease-bound callbacks. Reads and retries cannot manufacture producer facts.

Current Study access alone is insufficient to retrieve compiled inputs/results. Qualification must demonstrate the current source-right check for every captured exact source identity, plus current client/Study access, before the private artifact capability is returned and again after Edge I/O. No permission result is cached. Runtime operation/profile allowlists remain disabled until the actual actor HTTP → SQL queue → Worker/native → stored artifact chain and its negative cases have been exercised on exact owned components. Local experiment admission is not hosted deployment or scientific/business qualification.

## Proof and rollout

The opt-in `scripts/qualify-study-core.ts` harness addresses only the explicitly owned disposable `study894` project at loopback API port 56421. Coordinate a stable database generation with its owner before provisioning or verification. The private mode-0600 JSON config has `schemaVersion: lca.study-local-core-config.v1`, `projectId: study894`, `supabaseUrl: http://127.0.0.1:56421`, `publishableKey`, `serviceKey`, and an absolute `fixturePath` ending in `.json`. It must never enter Git or tool stdout.

Run with `deno run --cached-only --config supabase/functions/deno.json --allow-read --allow-env --allow-net=127.0.0.1 --allow-write=<owned-private-evidence-directory> scripts/qualify-study-core.ts provision --config <private-config-path>`. This creates three email-confirmed synthetic users through actual local GoTrue and writes their IDs/passwords only to the private fixture. The Database owner then seeds exactly those users' private profile/team roles (owner/member, outsider excluded), and writes `<fixturePath>.seed.json`, also mode 0600, with `{projectId,runId,teamId,actorIds,generation}` matching the fixture order. No prepared models, producer jobs, enabled profiles or numerical evidence are seeded by this harness.

Invoke the same command with `verify` instead of `provision`. Verification signs in through real Auth, starts an ephemeral IPv4 loopback listener running the actual handler and default authentication/SDK adapters, and exercises core capabilities, personal isolation, explicit team grants/revocation, idempotency/conflict, concurrent CAS, bound cursor invalidation, archive and cross-session recovery. It verifies that W06 producers remain unavailable. The private receipt records executed source-file hashes, runtime/dependency versions, database-owner generation, proof groups and fixture retention. Sessions are signed out and the listener's shutdown/finished promises are awaited on success or failure. Generated user/team/Study IDs remain private and explicitly owned until the main task resets that isolated project; never delete frozen history or disable its guards for cleanup. This local core HTTP proof does not qualify W06 production, hosted authentication, report/review/share or a business pilot.

`test/study_runtime_test.ts` exercises the actual handler, pinned SDK RPC/Storage transports, malformed JWT rejection, source recovery, typed selection, profile/capability negatives, validator bytes, deadline cancellation, fixed errors and post-I/O withdrawal. The byte-preserved cement fixture additionally proves consumption of actual W05 compiler output with declared coverage gaps and task-authored-model limitations. Seven actual W03 PostgreSQL 17 actor projections also pass v2 parsing and handler/SDK replay; their synthetic transport does not create live database or gateway authority. Synthetic replies and injected validation outcomes are explicitly local adapter proof. They do not prove SQL/RLS, native Worker execution, real exporter/source licensing, hosted authentication or production readiness. Cross-repository integration must bind actual Database transactions and Worker-produced artifacts before enabling the deployment allowlist. No deployment is performed by these tests or this source change.

## Opt-in owned runtime qualification

`scripts/qualify-study-runtime.ts` is restricted to the receipt-owned `study894` loopback stack and exact private configuration/fixture paths. It adds no hosted endpoint or default capability. Its mode-0600 config identifies only the owned transport environment and fixture files; secrets never enter command arguments or stdout. `provision` creates three disposable Auth accounts with a distinct Study537 namespace and saves the ownership ledger before account work. Database owns exact team roles, source rows, calculation descriptor, activation and its separate seed receipt.

After Database confirms the local-only configuration and quiet queue, `admit` starts the actual Study and generic worker HTTP handlers with normal Auth/SDK adapters. It cancels one real queued acquisition, rejects the generic Study job read/cancel route, discards another acquisition response and recovers it with the original key. It saves the API-issued identities and closes its listener/sessions. Only the separately owned Worker daemon may claim the remaining exact job. `verify` uses fresh Auth sessions/listener to recover that acquisition, obtain actual native/Storage preparation, validate/freeze the revision, prepare two frozen scenarios, submit/recover Runs and verify result bytes against independent bounded numerical expectations. It checks underlying private-source disclosure, generic-route denial, late cancellation and current Study grant revocation. No callbacks or successful result states are synthesized.

Run each phase with exact Deno and `--config supabase/functions/deno.json`, loopback-only network permission and the explicit owned read/write paths. Check the script separately with `deno check`; default tests import only its configuration guard and never provision accounts or start a listener. The output receipt binds executed source hashes, fixture/Database generation and actual API identities. It distinguishes local handler/SQL/queue/native/Storage execution from hosted gateway, business-pilot and complete-LCIA qualification. Failed attempts and unknown completion outcomes remain preserved; stop the exact owned Worker before destructive fixture cleanup and retain unresolved upload intents/artifacts for its source-bound reconciliation. Database owns data/config cleanup; Auth accounts and copied credentials are removed only after that cleanup receipt. Listener shutdown and session sign-out run on ordinary success/failure.
