# P3 Database / Edge service seam

Edge #550 and Database #906 agreed this additive wire before runtime implementation. The exact owner schemas and synthetic SQL shape fixtures do not establish real artifact bytes, OAuth execution or hosted admission. V2/V3 remain unchanged.

- Actor `api.qry_study_review_v1(p_request)` and `api.cmd_study_review_v1(p_request)` receive exact V4 requests. `operationMetadata` owns the query/mutation split. Database derives actor/client authority and actions; caller actor/evidence fields are rejected.
- Content I/O returns only `{kind:studyReviewIntent,intentId,operation,expiresAt}`. Service `svc_study_review_intent_resolve_v1(p_intent_id)` returns the strict `review_context.ts` wrapper: original V4 request, actor/client, currentState, nullable producerContext/share/export/artifact and fixed intent expiry. Wrapper actor/client identify the requesting actor. The service-only producerContext uses the existing P2 shape under the Study owner's current source/disclosure authority. Its server-owned V3 export request is distinct from the actual outer V4 request.
- `report.view` rebuilds the allowlisted view from exact P2 producer bytes. Its producer allocations/profile may be null; only the export-specific presence checks are relaxed. Numerical/content/frozen bindings remain checked. Reviewers gain no raw source/model/Run/full-facts access. Only the view/current state reach callers.
- `export.request` requires all preallocated identities and signing/renderer pins. `svc_study_review_intent_consume_v1(p_intent_id,p_completion)` consumes `{kind:validatedReviewExport,projectionArtifact,resourcesArtifact,bundleArtifact,manifest,receipt}`. Artifacts use `study/<studyId>/<artifactId>/{projection,resources,bundle}.json`; no overwrite. Manifest/bundle v2 bind immutable finalization and exact accepted historical IDs. Frozen P2 rows/manifest v1 bytes remain unchanged.
- `currentState.acceptedReviewIds` is the current eligible approving candidate set, allowing owners to select exact IDs without copying authorization rules. `finalization.acceptedReviewIds` is the immutable chosen subset. Finalized view/export snapshots use that historical subset (empty for explicit unreviewed), while current acceptance remains separate. Initial internal finalization needs a current non-author reviewer; independent review is unavailable.
- Delegation issue/revoke is first-party-only for the exact reviewing actor/client/report/hash/class/decision/predecessor. Maximum admission expiry is fifteen minutes, and one committed review consumes it once. Expiry does not erase a consumed historical decision; explicit revoke and current role/client checks invalidate acceptance. Comments never approve.
- Share view/download is recipient-only and resolves the exact persisted projection/bundle plus export/finalization metadata. The issuer manages metadata/revoke and uses ordinary report view/export read. Summary disclosure admits public or exact issuer-owned private sources and rejects unsupported private borrowing. Recipients gain no Study role. No anonymous URL or locator appears in public responses.
- Database performs live source/role/team/client/delegation/share checks before idempotent replay and every service resolution/consume. Edge re-resolves around each bounded Storage read/upload and before disclosure. Intent-bound output timestamps remain stable; live authority/state changes fail closed. Database clocks own domain expiry, while the existing monotonic Edge deadline bounds transport work.
- Default admission permits only capability.read with no profiles/classes/policies. Runtime allowlists intersect Database authority. `resource.actions.allowedMemberRoles` is server-derived: personal owner reviewer-only, team owner editor/reviewer/viewer, otherwise empty. Histories use opaque cursor and at most100 entries; current/accepted review arrays cap at64 to fit the unchanged renderer.

Public source: `contracts/lca-study/v4/{review,responses,view,codec,export}.ts`. Synthetic fixtures: `test/fixtures/lca-study-api/v4/{protocol,view,database-service-contexts}.json`. The SQL context fixture contains only isolated study906 synthetic identities/locators/hashes and no credentials; it proves shape/persistence, not actual file/signature production.

`export.download` is a query using exact `exportId` and existing export-read authority. Its intent/context operation is `export.download`, producerContext and share are null, export is the persisted V4 record, artifact is only its exact bundle capability. The public response is `{type:exportDownload,export,encoding:base64,bytes}`. Existing V3 artifact reads are unchanged.

Replay preserves immutable outcome IDs while freshly hydrating current state. Review replies require `{type:review,value:<originalReview>,state:<current>}`. Finalization replies retain original value alongside current state even after a newer finalization. Share/delegation replies keep identity and refresh current status/revocation/consumption. Consumers do not infer current authority from a cached completion snapshot.

Both `review.record` and `review.delegation.issue` reject `decision:withdraw` with null `predecessorReviewId` at the portable/Edge request boundary (`INVALID_REQUEST`). A supplied nonnull predecessor is not proof of a current head; Database verifies that state and rejects missing/stale withdrawal heads with `REVISION_CONFLICT`. Approve/reject may begin a new chain with null.
